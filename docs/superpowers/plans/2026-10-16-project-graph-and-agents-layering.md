# Project graph + AGENTS.md layering — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the context this repo costs an agent to navigate itself: a generated project
graph that replaces the read-and-grep walk, and an `AGENTS.md` that keeps only rules which
change behaviour, with the interpreter-CLI reference moved out behind a gate that proves
nothing was lost.

**Architecture:** `make graph` runs `tools/project_graph.sh` — POSIX sh, no network, reads
only the checkout — and writes `docs/PROJECT_GRAPH.md` (modules → their own includes and
stdlib includes; LSP 3.18 client→server methods marked answered/advertised; test-suite map).
The spec's method inventory is frozen in `tools/lsp_methods.tsv`, regenerated by hand from
LSP 3.18's `metaModel.json` exactly as `tools/keyword_gate.sh` regenerates `CANNOT_BE_NAME`.
`tools/agents_gate.sh` checks a required-token list captured before the split against the
union of `AGENTS.md` and `docs/seed7-cli.md`, so content may move but may not vanish.

**Tech Stack:** POSIX `sh`, `awk`, GNU Make, `python3` **only** in `tools/lsp_methods_regen.sh`
(the repo already depends on python3 for `tests/transcript.py`). Seed7 5.4.10 is not touched:
no file in `src/` changes in this plan.

**Spec:** there is no separate design doc — this plan is the design record for tooling that
changes no protocol behaviour. It argues from the measurements in *Background* below, which
are reproducible, and from `docs/superpowers/specs/2026-09-10-seed7-lsp-server-design.md`
§8 (milestones) and `AGENTS.md` (invariants 1–7).

## Global Constraints

- Nothing in `src/` changes. No capability is added, removed or renamed. Invariants 1–7 stay
  satisfied by construction; the graph only *reports* them. **Carve-out (R24):** Task 7 Step 0 may
  edit COMMENT lines in `src/` that point at text this plan relocated " comments only, so the
  behaviour, signatures and asserted strings of every module stay exactly as they are, and `make
  test` is the proof.
- Red first: every assertion is written, run, seen to fail for the named reason, then made
  green. Both new suites are written after the artifact they check — say so in the commit and
  name the mutation that reddens each one.
- House tool style (`tools/keyword_gate.sh`, `tools/corpus_scan.sh`): `#!/bin/sh`, `set -eu`,
  header comment with `WHY` / `HOW` / `shortcut:` / `Usage:`, and a comment saying explicitly
  whether it is wired into `make test` and why.
- Suite contract: a total line matching `^[a-z0-9_]+: [0-9]+ checks, 0 failed$`. The Makefile
  grades that line, never `s7`'s exit status.
- Fast-tool rule: anything wired into `make test` must finish in seconds (the 7.7 s baseline).
  A tool that walks the whole Seed7 distribution stays out, like `corpus_scan.sh`.
- Generated files carry a "GENERATED — do not edit" first line and are committed; the suite
  asserts the committed copy equals a fresh run, so staleness fails the build.
- No invented numbers: size ceilings and counts are pinned from the artifact a task just
  produced, in that task.
- A suite grep that relies on an ERE metacharacter (`+`, `?`, `|`, `()`) runs under `grep -E`, and
  every check pattern must be tried against the mutant it is meant to catch before it is kept.
  Measured in Task 2 round 1: my `seed7_\.s7i` scored 0 on the clean tree *and* 0 on the mutant,
  and a BRE `grep -c` with `+` scored 0 where `-E` scored 12. A pattern that cannot match the
  mutant is not a check, however correct it looks. (R12)
- Clean up after probes: no binaries, no `profile_out`, and `git status --porcelain -uall`
  empty at the end of every task.
- The method inventory is LSP **3.18** only, and only `clientToServer` + `both`.

## Task 1: AGENTS.md requirement gate (the safety net for Task 5)

**Files:**
- Create: `tools/agents_gate.sh`
- Create: `tools/agents_required.txt`
- Modify: `Makefile` (add `TESTS_SH := agents`, replace the `test-%` rule with the
  dispatching one, add the target to `.PHONY` and `test:`)
- Test: this task's own deliverable is the suite.

**Interfaces:**
- Consumes: `AGENTS.md` as it stands.
- Produces: `tools/agents_required.txt` — one token per line, `sh`-quoted-free, each token
  required to appear in **at least one** of `AGENTS.md` `docs/seed7-cli.md` (the union is
  read in order; a file named in the list that does not exist yet counts as empty, not fatal).
  `sh tools/agents_gate.sh` prints `agents: N checks, M failed`, exits 1 iff `M` > 0.
  The Makefile target is `make test-agents`.

- [ ] **Step 1: Freeze the required tokens from today's file**

Six mechanical extractor classes, no judgement calls, union sorted (was four before R8 added
the moved-region class and R9 split the invariant rule in two):

```sh
{
  grep -oE '^## .*' AGENTS.md                                          # every section header
  grep -oE '[A-Za-z0-9_/.]+\.(sd7|s7i|c|h):[0-9]+(-[0-9]+)?' AGENTS.md  # every citation
  grep -oE '[0-9]+ (checks|entries|identifiers|lines|bytes|ms|kB|characters)' AGENTS.md
  grep -oE '^[0-9]+\. [^ ]+[^ ,;.]*' AGENTS.md                           # every invariant, by number
  grep -oE '^[0-9]+\. Only [^ ]+[^ ,;.]*' AGENTS.md                      # AND the owner path of those that have one
  # R8: the material Task 5 MOVES. Code-shaped backticked literals from the two moved regions,
  # kept only if they occur nowhere else in AGENTS.md — a token that also survives elsewhere is
  # a check that cannot fail. Lines are 50-59 (the profiling paragraph) and 97-136 (the five CLI
  # bullets); verify the ranges still bound that material before using them.
  sed -n '50,59p;97,136p' AGENTS.md | grep -oE '`[A-Za-z0-9_.,/+:-]{6,}`' | tr -d '`' | sort -u |
    while read -r tk; do
      if [ "$(sed -n '1,49p;60,96p;137,$p' AGENTS.md | grep -cF -- "$tk")" -eq 0 ]; then
        printf '%s\n' "$tk"
      fi
    done
} | sed 's/ *$//' | LC_ALL=C sort -u > tools/agents_required.txt
wc -l tools/agents_required.txt
```

The last class is the one that makes the net bite, and the char class admits **no space**, so
it can only reach single-token literals. Measured on today's file the whole class yields
exactly 8: `analysisOf`, `analyzeAll`, `collectSyms`, `-g-debug_c`, `profile_out`,
`src/analysis.sd7:333`, `tests/occurrences_test`, `tests/occurrences_test.sd7` — and all 8
occur **nowhere outside** the moved regions, which is the property a regression token needs.
Space-bearing literals in the moved text (`s7c -p -O2 -l src <file>`, `usecs / calls / place /
name`) are unreachable by this class; catching them needs its own extractor rule, not a wider
char class. Do not add bare flags (`-p`, `-O`, `-s`) either: as `-F` substrings they are
satisfied by unrelated text elsewhere, so the check could never fail.

The two invariant rules are a deliberate union: `^[0-9]+\. [^ ]+…` catches owners with no file
path (5 `Capabilities`, 6 `renameDecision`, 7 `Outbound`) and `^[0-9]+\. Only …` keeps the
owner PATH of 1-4, which is what tells a reader which module a violation lives in. Keep both,
with a comment saying why — dropping the narrow one ships a weaker net than the round-0 list.


Commit the file verbatim, with its line count in the message. If an extractor yields 0 lines the
rule is wrong for this file — fix the rule before committing, because a silently empty class is
exactly the decorative-check failure `AGENTS.md` forbids.

- [ ] **Step 2: Write the gate**

`tools/agents_gate.sh`: for each required token, `grep -qF -- "$tok" $FILES` over
`AGENTS.md docs/seed7-cli.md` (whichever exist), count pass/fail, print the repo's total line
`agents: N checks, M failed`, and on failure print each missing token on its own line prefixed
`MISSING `. Exit `M == 0 ? 0 : 1`. Header comment must state WHY (content may move, may not
vanish), HOW, the `shortcut:` line (a token list frozen today cannot catch a token that was
never in `AGENTS.md` — the list is a regression net, not a specification), and Usage.

- [ ] **Step 3: Run it and verify it passes on sight**

Run: `sh tools/agents_gate.sh; echo $?`
Expected: `agents: <N> checks, 0 failed`, exit 0. Passing on sight proves nothing about whether
it can fail — that is Step 4.

- [ ] **Step 3b: Confirm the list is a net, not a mirror**

Before the mutation, answer one question with numbers: how many required tokens occur **only**
inside the regions Task 5 moves (lines 50-59 and 97-136)? It must be at least 3. If it is 0 or 1,
the gate cannot see the split at all — fix the extractor here, in Task 1, rather than meeting the
surprise in Task 5. Record the count in the commit message.

- [ ] **Step 4: Prove the gate can fail (mutation, not a fixture)**

```sh
cp AGENTS.md /tmp/AGENTS.keep
grep -v 'Only `src/analysis.sd7`' AGENTS.md > /tmp/mut && cp /tmp/mut AGENTS.md
sh tools/agents_gate.sh; echo "exit=$?"     # must be nonzero, must print a MISSING line
cp /tmp/AGENTS.keep AGENTS.md && git diff --stat --exit-code AGENTS.md
```

Expected: exit 1 with the invariant token in `MISSING`, and then a clean `git diff` proving the
revert. If the gate stays green, the token list or the grep is broken — fix before committing.

- [ ] **Step 5: Wire the Makefile — ONE `test-%` rule that dispatches on which file exists**

Do not add a second `test-%` pattern rule. Attempted in pre-flight: with two same-stem rules — a
shell rule and the house `.sd7` rule — `make test-graph` ran the **s7** recipe and died with
"tests/graph_test.sd7: No such file or directory", and `make test-jsonw` ran the shell recipe and
died on a variable make had emptied. Which rule wins depends on file order and on what already
exists, so the failure mode is a suite that silently stops running while `make test` prints green
lines — this repo's named defect (ledger R1).

Replace the existing rule with one that resolves the suite file by convention, and widen its
target list:

```make
TESTS_SH := agents      # Task 2 appends `graph`. Shipping it here would point `test-graph` at
                        # a suite that does not exist yet and break `make test` in this task.

$(addprefix test-,$(TESTS) $(TESTS_SH)): test-%:
	@f=tests/$*_test.sd7; [ -f "$$f" ] || f=tests/$*_test.sh; [ -f "$$f" ] || f=tools/$*_gate.sh; \
	 case "$$f" in *.sd7) out=$$($(S7) -q -l $(SRC) $$f 2>&1);; *) out=$$(sh $$f 2>&1);; esac; \
	 printf '%s\n' "$$out"; \
	 printf '%s\n' "$$out" | $(G) -q $(S7TOTAL)
```

`TESTS_SH` is a target list, not a variable table — the three filename conventions are the whole
lookup (`tests/<name>_test.sd7`, then `tests/<name>_test.sh`, then `tools/<name>_gate.sh`). Add
`$(addprefix test-,$(TESTS_SH))` to `.PHONY` and to `test:`'s prerequisites. Task 2 then only
appends `graph` to `TESTS_SH` and adds the `graph` target — it touches no rule.
Run: `make test`
Expected: the 19 `.sd7` totals unchanged (936 checks today) plus
`agents: N checks, 0 failed` — 20 totals, 0 failed, still seconds.
Then prove the wiring is not decorative: `make test-agents` alone prints the same total line, and
`make test-nothing` FAILS (no file resolves, so nothing grades). A rule that matches anything is
the silent-green hazard R1 exists to avoid.

### Task 2 addendum (R11, from its review: 8 checks, not 6)

The review confirmed the artifact but found the net weaker than the plan's own words. These four
changes are part of Task 2's acceptance; the check count becomes **8**, which renumbers the later
arithmetic (Task 3 = 15, Task 4 = 18).

1. **Replace check 2.** It grepped the literal `" x "`, so any other false edge from a comment
   (say `include "rpc.sd7"` inside prose) passed, and on empty output `grep -c` prints 0 so the
   condition passed vacuously. It must be a whole-row equality, which is non-vacuous and subsumes
   "and nothing else":

   ```sh
   check "blocks.sd7 row is scan.sd7 and nothing else" \
         'test $(sh tools/project_graph.sh | grep -cE "^blocks\.sd7 +[0-9]+ +scan\.sd7$") -eq 1'
   ```

2. **New check: the `seed7_05.s7i` exclusion is a content property, not a freshness property.**
   All 28 modules include `seed7_05.s7i` on line 1, so deleting that `case` arm adds a universal
   edge to every row and the ONLY red is `committed artifact is fresh` — which `make graph` then
   erases. `test $(sh tools/project_graph.sh | grep -c "seed7_05\.s7i") -eq 0—**grep the
   generator's stdout, never the committed artifact**, or re-blessing erases the evidence. Hazard
   for Task 3/4, which append sections to the same stream: keep the literal `seed7_05.s7i` out of
   any later section, or scope this check to the modules section when they land.

3. **New check: the feature rows.** `^[a-z0-9_]+\.sd7 +[0-9]` cannot match a `features/...` row
   (`/` is outside the class), so all 12 feature rows could vanish with only freshness noticing:
   `test $(sh tools/project_graph.sh | grep -cE "^features/[a-z0-9_]+\.sd7 +[0-9]") -eq $(find src/features -maxdepth 1 -name '*.sd7' | wc -l)`
   " `-E`, per R12. Known limit measured in round 1: in a tree with no `src/features` the right-hand
   `find` collapses to 0 too, so this check passes `0 -eq 0` and cannot see that case; the stderr
   check carries it. The generator's `shortcut:` comment must say exactly that, not claim this
   check reddens.

4. **Delete the trailing `| sed 's/[[:space:]]*$//'`.** POSIX sh has no `pipefail`, so a fatal
   inside `generate()` still exits 0 through the pipe and `make graph` happily writes a truncated
   artifact. Choose the format per row instead (two-field form when a row has no includes), which
   removes the pipeline, the comment above it, and one process. Also `sort` — `sort -u` on the
   include lists, and rename check 1 to `generator writes nothing to stderr` (it proves the stderr
   half; check 8's freshness proves the stdout half).

Accepted as a documented limit rather than code: `for x in $(find ...)` word-splits paths and the
suite uses fixed `/tmp/g1`, `/tmp/g2` (both are the brief's shape, and a future `make -j test` or a
shared `/tmp` is the day they bite) — put a `shortcut:` line naming that.

- [ ] **Step 1: Write the failing checks**

  Three commands in this step were broken as originally written and Task 4 had to repair them
  (R17). The shapes that work are in the shipped `tests/graph_test.sh`; the rules they teach:
  (i) `sed -n "s/^TESTS(_SH)? *: *//p"` is BRE, where `?` and `(...)` are literals, so it matched
  nothing and a derived count came out 1 instead of 5 — use `grep -E` or a POSIX character
  class, and assert the count is plausible before trusting it;
  (ii) a condition of the form `$(… | grep -c x)` inside a check that also runs `true` counts the
  output of `true`, so the check can pass on the shape of a string rather than on the tree;
  (iii) `comm <(…) <(…)` is process substitution, a bash-ism, and this repo runs suites with `sh`.
  Rewrite with temp files or a loop. A suite that only runs under bash is a suite that silently
  stops running.

Append to `tests/graph_test.sh`:

```sh
check "spec inventory is 75 client->server|both" \
      '$(wc -l < tools/lsp_methods.tsv) -eq 75'
check "answered rows equal the dispatcher's method list" \
```
