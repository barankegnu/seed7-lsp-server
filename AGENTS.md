# AGENTS.md

Work here as a careful maintainer of a language server, not an author of Seed7
tutorials. This file holds what no config confesses. The commands are in the `Makefile`.
The design authority once named here,
`docs/superpowers/specs/2026-09-10-seed7-lsp-server-design.md`, was deleted in `fca09be`
and has no successor: behaviour is answered by this file, by the evidence in
`docs/seed7-cli.md`, and by the interpreter — measure rather than invent an authority.
Executed plans sit in `docs/superpowers/plans/` and describe the tree as it was when they
were written, not as it is.

The module/method/suite shape is generated at `docs/PROJECT_GRAPH.md` — read it before walking
`src/`, and regenerate it with `make graph` when `src/` changes.

This file keeps rules, not their evidence. `docs/seed7-cli.md` holds the `s7`/`s7c` options
and, below them, the measured figures, citations and decision history the rules here point at.
Read it when a figure or a citation bears on your change. A pointer is not a demotion: the rule
stays here and is enforceable from here; only its evidence is one hop away.

## Every change

Red first. Write the check, run it, confirm it fails for the reason you claim, then
implement. `make test` before and after. A check that cannot fail is worse than no
check: when a safety net becomes unreachable from real input, delete the assertion
rather than inventing a synthetic trigger. To prove an assertion can fail, mutate one
production branch and require that named check to go FAIL. Do it after
committing, and revert per file — `git checkout -- .` restores from the index and will
silently undo work you have not committed yet. `git checkout HEAD -- <file>` is the same trap one
level finer: it discards your uncommitted edits to *that* file, so mutate-and-revert that way only
when nothing in the file is uncommitted — otherwise restore the exact bytes you changed, or the
check you just proved vanishes together with the mutation. When a review or a probe contradicts a
commit message, correct the message in the next commit — the correction is the finding.

Two mutation-proofing rules this branch learned the hard way: (1) before demanding a
mutation, check the mutant is not **semantically identical** — `if n > MAX then n := MAX`
and `if n >= MAX then n := MAX` are the same function because the assignment is a no-op
at `n = MAX`, so no black-box input can separate them and the demanded proof was
unsatisfiable by construction; (2) **"no fixture reaches it" is not "no input reaches
it"** — there the honest answer was a missing fixture, not an equivalent mutant. And a probe method: to prove an `include` is unused you must exercise
the module's **own** include list from a standalone probe, with a positive control proving
the probe can fail — a test file that already includes the same modules makes any deletion
pass for the wrong reason.

Two measurement rules, both bought with a wrong number that reached a document or a
commit. A byte count must come from the artifact the product emits — the wire
`Content-Length` — never from re-serialising a parsed copy. And a probe must print a
sentinel that the harness requires before any payload is counted as a result. (`Every change —
mutation and measurement provenance` in `docs/seed7-cli.md` holds both stories.)

Tests written after the code exist are a different thing from tests written first, and saying
"coverage" does not make them the same. When a check is added to code that already works — inherited,
or fixed by someone who left no report — it passes on sight, which proves nothing about whether it can
fail. Label it in the commit, and prove it by mutation: revert or widen the specific production
decision and name the check that goes red. If no mutation reddens anything, the check is decorative and
should be said so out loud.

A green check on a fixture the product never produces is decorative the same way, and no mutation of
production code will tell you. When a check pins a position, a range or an offset, measure the corpus
for its shape and give the fixture that shape: the disclosure telling the user their unsaved library
edits are invisible was pinned against a library whose first line held a declaration, while all 265
`lib/*.s7i` begin with an empty line — so its range collapsed to zero width on every real input and the
suite stayed green. The story and the measurement: *The disclosure, and what pins it* in
`docs/seed7-cli.md`.

## Seed7 traps

Each of these cost a debugging cycle. Seed7 is not Python and will not warn you first.

- Which names the language refuses is measured, not remembered: `src/keywords.sd7`'s
  `CANNOT_BE_NAME` is regenerated by `tools/keyword_gate.sh`, which probes each word and exits
  1 if the array drifts. `step`, `key`, `len`, `range` are on it and fail as parameters AND as
  locals; `type`, `proc`, `result`, `enum`, `and`, `or`, `div` are NOT. Never extend or shorten
  the array by hand; run the generator.
- A `local` variable cannot be initialised from a parameter of the same function.
  Declare with a constant, then assign in `begin`.
- `key`, `len` and `line` are taken by the language and library. Choose other names.
  So is `sum` — and a result variable that collides with a library function is worse than a
  warning, the whole declaration silently fails (`DECL_FAILED` after a `NO_MATCH`).
- A `func` with a `result` clause **assigns** its result variable; Seed7 returns it
  implicitly. Writing `res := x; return res;` does not match at analysis time, and a bare
  `return` in a `proc` raises `PROC_EXPECTED`. `is return expr;` is the other correct form.
- Strings are `"...\"..."`. There are no single quotes, and `""` is not escaping.
  Tab inside a literal is `\9;`. A char literal cannot hold the escape character or a quote
  the way you expect: `'\'` does not parse — the escape eats the closing quote. Use
  `chr(92)`/`chr(39)` and name them — `scan.BACKSLASH`/`scan.APOSTROPHE`.
  The quote character is written `'''` — open, the quote as content, close — and `''''` is
  the parse error ("Character literal exceeds source line"). Verify a spelling with `s7`
  before coding to it.
- At statement level `<&` writes to the output stream; assignment is `&:=`. Worse,
  `A <& B < C` parses as a *comparison* and quietly yields `FALSE` — which is how a
  capabilities payload once shipped `{"capabilities":FALSE}`. Compose JSON with
  `jsonw.sd7`, never by concatenation.
- `&` concatenates strings and rejects an integer; use `str(n)`. `startsWith`, not
  `beginsWith`; `length`, not `strlen`; `pos(a, b) <> 0` for containment;
  `integer(stri)` and `integer(stri, base)` to parse.
- The catchable exceptions are the 14 in `seed7_05.s7i:280-294`. `SIZE_ERROR` does not
  exist. `string(jsonValue)` on a non-string raises `ILLEGAL_ACTION`, so switch on
  `category(v)` instead of catching.
- `hash [k] v` needs a named type: `const type: h is hash [k] v;`, empty value
  `h.EMPTY_HASH`, removal `excl(h, key)`, assignment `h @:= [k] v`.
- A file that defines `main` cannot be included by a test (redeclaration). That is why
  `main.sd7` and `lsp_server.sd7` are separate files.
- For s7/s7c options, profiling and optimizer knobs: `docs/seed7-cli.md` — never guess a flag.
- `-tefs` is not a flag set for the server. `-te` prints every **caught** exception to **stdout**,
  and `rpc.sd7`'s `atKey` catches `INDEX_ERROR`/`ILLEGAL_ACTION` on the request path deliberately,
  so a `-te` build writes non-frame bytes into the LSP stream. Trace a running server with `-tfs`.
  The release and debug lines, and the measurement that separated them: *Build — the two flag sets*
  in `docs/seed7-cli.md`.
- `s7` reports analysis errors on stderr **and exits 1**, with nothing on stdout — measured for a
  syntax error, a `NO_MATCH`-style failure, an unclosed comment, a redeclaration and a missing
  `include` (upstream `da2feb38`, "Errors trigger an exit code of 1", 2026-09-25). The exit-0
  shapes both print on **stdout**: `*** Declaration for main missing`, what a `main` that fails to
  declare reports, and `*** Sourcefile missing` for an invocation with no file at all. Uncaught
  exceptions print to **stdout** and exit 1, unchanged — and so does a file that does not exist,
  which reports `*** File "<path>" not found` at exit 1. So never judge a run by its status code,
  and never let an exception reach stdout — it corrupts the protocol channel. A test suite inherits
  the exit-0 half: one whose `main` does not declare prints that line, exits 0, and would pass the
  recipe unread, so `Makefile`'s `test-%` rule grades the suite's own `N checks, M failed` line — a
  grading that holds whichever way the interpreter exits.
  The ten probes, their commands and their stdout byte counts: *Seed7 traps — the exit code,
  re-measured* in `docs/seed7-cli.md`.
- `include` of our own modules needs `-l src`. Seed7 has no module system, so every
  file repeats `$ include "seed7_05.s7i";` and the includes it uses. Subdirectories work
  (`include "features/hover.sd7"` resolves against `-l src`), which is how `src/features/`
  stays out of the dispatcher's way.
- `str(ch)` DOES work — `str(chr(128512))` returns a one-character string, and `chr(n)` is how a
  code point becomes text. What fails is `string(ch)` and concatenating a char (`ch & ""`,
  `"" & ch`, even `chr(195) & chr(165)`): none match. Slicing the source (`stri[i .. i]`) is still
  what `jsonw.sd7` does, but it is a choice, not a necessity.
- `writeln` and `write` take exactly ONE argument. `writeln("a=", n)` does not match — compose the
  line with `<&` and `str()` first. An argument list that fails to match inside `main` reports
  only "Declaration of main failed", which reads like a broken body.
- `gets` on a UTF-8 file counts CHARACTERS, not bytes (`utf8.s7i:132` → `utf8_gets`), so handing
  it a `Content-Length` over-reads any body holding non-ASCII. `transport.readFrameBody` exists
  because of this; `readln` and `getl` are the safe reads.
- Safe is about the count, not the bytes: `getln`/`gets` on a `STD_UTF8_IN` stream raise
  `RANGE_ERROR` at the first byte sequence the decoder refuses, and those reads live in
  `transport.sd7` — **outside** `main.sd7`'s handler block, so an unguarded one writes its trace
  onto the protocol channel (one `0xFF` in a frame body did, and the session exited 1). Guard a new
  inbound read at its own site. Which sequences the reader refuses is measured, and an overlong
  `C0 80` is not one of them (*Protocol decisions — the framing outcomes, measured* in
  `docs/seed7-cli.md`).
- A Seed7 array literal is `[]("a", "b")`. `("a","b","c")` does not match and `{...}` is a
  block, so a brace-form array declaration fails somewhere far away in the error tree.
- `in` and `not in` work for hashes and sets, but not for arrays: `k in arr` fails to
  match for any `k` and any `array` type — `in` has no array overload. It does not parse
  either when the left side is a struct-field select (`syms[i].sign not in
  shown`); `analysis.listed()` exists because of it.
- Declare before use: a `func` cannot call a helper defined later in the file, so the small
  total wrappers in `analysis.sd7` sit above the walker that uses them.
- Seed7's `and`/`or` short-circuit, but a long `or`/`and` chain of parenthesised
  comparisons can fail to *match* — split the predicate into small `const func boolean:`
  one-liners (see `doc_store.isAlpha`/`isDigit`/`nameChar`).
- `stri` is not a type name; the type is `string`. `var stri: text is ""` fails with
  "Match for {var stri : text is {"" } } failed".
- `NULL_FILE` does not exist; the null file constant is `STD_NULL`.
- `gets(<utf8 file>, -1)` raises `RANGE_ERROR` at `ut8_rtl.c(586)`; a `readln` loop reads
  the same file. Relevant to R-F10, which needs to read a file from disk.
- A slice whose low bound exceeds its high bound is the **empty string, silently** —
  `text[3 .. 2]` has length 0. So "I deleted this bounds guard and every suite stayed
  green" proves the guard is *harmless to remove*, never that its `FALSE` branch is
  unreachable — `scan.maskOf`'s gap guard is that case, and its `FALSE` branch fires more often
  than its `TRUE` one (*Seed7 traps — the bounds-guard case* in `docs/seed7-cli.md`).
- `main` takes **no parameter** here. A parameterised `main` (probed with both
  `arguments` and `argv`) was not recognised by 5.4.10: `*** Declaration for main
  missing`, exit 0, and the probe silently never ran. The idiom the standard library uses is a plain
  `main is func` reading `for a range argv(PROGRAM) do` (`prg/echo.sd7`, verified).
- `&` copies its whole left side, so a per-token append (`s := s & token` in a loop) is quadratic.
  `&:=` is the in-place `STR_APPEND` — it grows the buffer, so the cost is amortised linear. The
  evidence and the measured ratio live in *Every change — the mask rebuild cost, measured* in `docs/seed7-cli.md`.

## Invariants — a violation is a defect, not a style preference

1. Only `src/analysis.sd7` imports `progs.s7i`. `grep -rn 'progs.s7i' src/` must show
   one line. Feature files receive `symRec` records; the temptation to read a `reference`
   directly is why this one is here.
2. Only `src/doc_store.sd7` converts LSP positions to string offsets.
3. Only `src/utf8bytes.sd7` **declares** the width rules: `utf8CharLength`,
   `utf8Length`, and `utf16CharLength` — and the surrogate bounds (`isHighSurrogate`,
   `isLowSurrogate`, `isSurrogate`), because the writer that must not emit bytes no JSON decoder
   owes the server (`jsonw`) and the reader that folds a pair (`rpc.joinSurrogates`) have to agree
   on where that range is. `src/transport.sd7`, `src/scan.sd7`, `src/doc_store.sd7`,
   `src/jsonw.sd7` and `src/rpc.sd7` include it; nothing else re-derives a threshold.
   `src/transport.sd7` owns every **outbound byte count** — `Content-Length` is its
   arithmetic and no other file emits one. `src/doc_store.sd7` owns position conversion
   and may consume a byte-valued column only to turn it into a character column
   (`charColumnForBytes`/`lspRangeBytes`), never to emit a byte count.
4. Only `src/*.sd7` and `src/features/*.sd7` build LSP response shapes; `analysis.sd7`
   returns Seed7-shaped data and knows nothing about LSP.
5. Capabilities are static in `InitializeResult`. No dynamic registration. And a
   capability is only advertised once its method is answered: `diagnosticProvider`
   shipped ahead of `textDocument/diagnostic`, which told pull-capable clients to
   ignore the push diagnostics we really did send.
6. `renameDecision` in `src/features/prepare_rename.sd7` is the ONLY rename refusal predicate, and
   `inScope` in `src/occurrences.sd7` is the ONLY place scope is applied. A second copy of either is
   how you get "accepted by `prepareRename`, edited by `rename`" — which the milestone exists to
   prevent. Both read the same `occurrencesOf` pass (invariant: one pass per request).
7. Outbound text goes through `jsonw.sd7`. `str()` on a `jsonValue` is the `literal()`
   path that emits `\8364;` for `€` — invalid JSON.
   `grep -rn 'addStr(w, str(' --include='*.sd7' src/` must stay empty. The greps are
   recursive (`src/`, not `src/*.sd7`) because M3 put feature code in `src/features/`.
8. A position conversion walks **its own line**, never the document. `doc_store.lspRange` counts a
   column with `unitsOfPrefix(doc.text, start, ch)` — `start` is `doc.lineStart[lineIdx]` — and
   `lspRangeUnits` counts with `lineUnits`; a helper that instead sums widths from index 1 is
   `utf16Before`, which this branch deleted because two of its callers were on the `didChange` path.
   Same rule one level up: `blockRegions` is scanned once per request, and `enclosingRegionsFrom`
   filters the list the caller holds — `enclosingRegions` was deleted for doing the scan per position.
   Cost of violating it is not a wrong answer but an unmeasurable one: the fix that walked from index 1
   cost 3.46 s per diagnostics publish on `lib/shiftjis.s7i` against 997 µs for the line-bounded one.
   Figures, commands and the equivalence sweep: *Every change — the two hot paths, measured* in
   `docs/seed7-cli.md`.

## Protocol decisions that are easy to undo by accident

- Position→token is **left-of-character**: a client hovering the identifier that starts at
  column `n` sends `character: n`, so the token is the one *ending* at `n`, not starting at
  it. `doc_store.wordAt` owns that rule; do not re-derive it in a feature.
- Positions are 0-based line/character in **UTF-16 code units**; `utf8.s7i`'s
  `STD_UTF8_IN/OUT/ERR` are mandatory (plain `STD_OUT` raises `RANGE_ERROR` on
  non-ASCII), and `Content-Length` is the **byte** count while `length()` counts
  characters.
- Framing is three-way, and each way is pinned by a named check in `tests/transcript.py`. An
  absent `Content-Length` logs `frame without Content-Length ignored` and **keeps reading** — the
  frame behind it is still answered and the session can still end at 0. An unparsable value —
  non-digits, negative, over `MAX_FRAME_BYTES`, or **digits too wide for `integer()`** — makes the
  frame's end unknowable: log `invalid Content-Length '<value>'`, stop reading, exit **2**; the
  branch order in `readMessage` is what keeps that to ONE framing line per fatal frame. A byte
  sequence the reader refuses, in a header line or in a body, logs `<where> is not valid UTF-8` and
  exits **2** with only frames on stdout — that is the case which used to write an
  `Uncaught exception` trace onto the protocol channel and exit 1. Recovering a desynced
  byte-counted stream is not possible. Two limits, stated rather than hidden: "refuses" is the
  reader's own set, not every invalid sequence (an overlong `C0 80` decodes to `chr(0)` and is
  served); and a fatal byte in a **body** leaves the bytes already read in hand, so the server
  answers one `-32700` and then exits 2 — a body that arrived and does not parse is a real Parse
  error, and from outside the pair looks like a bug. The sessions, the frames and the commands:
  *Protocol decisions — the framing outcomes, measured* in `docs/seed7-cli.md`.
- `-32700` with a `null` id for a non-JSON body; `-32600` for a request after `shutdown`;
  `-32002` for traffic before `initialize` — answered under the id that traffic sent, string or
  number, measured with `"id":"x1"` and `"id":"s1"` in a session that never initializes;
  `-32601` for an unknown request, and silence for an unknown notification.
- The `exit` notification's status code is a decision, not a side effect. `lsp_server.sd7`'s
  `exit` arm answers `exit(0)` only for a session that saw both `initialize` and `shutdown`, and
  `exit(1)` otherwise — and it runs even before `initialize`, because `main.sd7`'s gate names
  `exit` beside `initialize`. Do not collapse those two calls to one `exit(0)`: the spec's rule
  keys on `shutdown` having been received, and this server refuses `shutdown` before `initialize`,
  so a refused shutdown can never earn the 0. `main.sd7`'s tail is the *other* ending, a stream that
  stops without an `exit` notification, and a Seed7 `main` that simply returns reports 0 (measured,
  interpreted and compiled) — so that path is 0 unless `framingFatal` makes it 2. The sessions, the
  frames, and the two `transcript` checks that already pin the 1: *Protocol decisions — the exit
  code and the id on the wire, measured* in `docs/seed7-cli.md`.
- Full text sync: the **last** `contentChanges` element holds the whole text.
- A truncated buffer is the normal state while typing, so `END OF FILE`-class analyzer
  messages publish as `DiagnosticSeverity.Information`. Match that class by substring:
  those messages end in a quote character, so a suffix test never fires — and
  `errorType` cannot key it either, because EOF also appears *inside* the message of
  `EXPECTED_SYMBOL` (`";" expected found "END OF FILE"`), not as its own member.
- An empty buffer — the first state of a new file — reports `SYSTEM_MAIN_MISSING`, so
  that one kind is downgraded to Information too, keyed on `parseError.error`. Do not
  expect the member on a file that has its `$ include "seed7_05.s7i";` line: with the
  essential include present, a main-less program analyses clean.
- `parseError.columnNumber` is a 1-based **UTF-8 byte** offset from the line start — the
  scanner's *current position at raise time* (`IN_FILE_TELL()` minus the line start in
  Seed7's `src/error.c`), so it names the byte just **after** a token-level error's
  offending token, and only a mid-token raise like `ILLEGAL_STRING_ESCAPE` names a byte
  inside the token. `lspRange` takes a character column, so analyzer columns go through
  `lspRangeBytes` and nothing else does. Consequence: `[col, col+1]` marks the character
  *after* the token for `EXPECTED_SYMBOL` and the illegal-character class, and inside the
  escape for `ILLEGAL_STRING_ESCAPE`. Pinned by three checks in
  `tests/analysis_test.sd7`; change the interpreter's convention and those checks go red.
  Their columns and fixtures: *Protocol decisions — the analyzer-column derivation* in
  `docs/seed7-cli.md`. Re-measure from there before you restate a number.
- `rename` refuses when the declaration line holds more than one record of the name. Seed7 lets a
  parameter share its routine's name, and the index has no column for a declaration, so choosing by
  line would sometimes rewrite the wrong symbol. Refusal on a write is the rule — do not "fix" the
  over-refusal with a column test unless regions become column-aware.
- `rename` also refuses when the symbol's own scope window holds the same spelling written after a
  `.' — a record field (`counter := counter + box.counter;`). The flag is `occurrence.dotPrev`,
  stamped in `occurrencesOf` (the only pass that knows the previous token), and the predicate is
  `occurrences.scopeHasFieldAccess`, which applies scope: a field access in another routine must
  not refuse this one's rename, and `features_test.sd7` pins that control. Measured cost: a
  **global** refuses on a field access anywhere in its file, because a global's window is the whole
  document. `references` keeps the over-inclusive list but now sets `unresolved` for it — spec
  12.2's split, read may over-include, write must not.
- Column 0 is the *object-form* error path (`storePositionedErrorLine`), not "all
  semantic errors": `NO_MATCH`, `DECL_FAILED`, `REDECLARATION`, `PREVIOUS_DECLARATION`
  and `UNCLOSED_COMMENT` arrive with 0, and `UNCLOSED_COMMENT` carries the line the
  comment *opened*. Ask `lspRangeBytes` for an absurd column and let it clamp.
- `errorType` has 67 identifiers in the interpreter's C enum; the 14 catchable
  `EXCEPTION`s in `seed7_05.s7i:280-294` are a different set (15 names, one of them
  `OKAY_NO_ERROR`). Both counts are right; do not "reconcile" them.
- `#` is both the line-comment introducer and the radix marker of `16#beef`.
  The scanner decides, because it knows whether it is inside a number token.
- `analysable` is the ONLY trust predicate. Every `analyzeAll` and every `publish` call site
  must consult it — F1 existed because that rule was true of `analyzeAll` and not of `publish`.
- The document's own records come first. `analyzeAll(...).syms` is ordered by `collectSyms` in
  `src/analysis.sd7`, and every consumer that *truncates* or takes the first record for a name
  re-ranks it in its own passes with `isBufferFile`: `definitionResult`, `emitSyms`,
  `buildClasses`. `hoverText` and `signatureHelpResult` do not — they answer from the producer's
  order and carry a `shortcut:` note saying so, which is why the ranking's user-visible guard is
  the pair of `hover`/`signatureHelp` pins in `tests/transcript.py` plus `rankShape` in
  `tests/analysis_test.sd7`. Give either of those two a `wantOwn` pass and no wire input can
  redden the ranking any more: `rankShape` is all that is left, so re-check that claim in the
  wire suite before re-sorting anything. Overloading a stdlib name is ordinary Seed7, and before
  this rule held `definition` listed nine library overloads of `length` ahead of the user's own
  and `semanticTokens` marked the user's declaration `defaultLibrary`.

## Do not "fix" these

- Analysis executes the analysed code. It is a property of using the interpreter as the
  parser, not a bug to route around — see the README's security section, which is the
  single source of truth for it, including why compiling is not an escape: `s7c` produces its
  call-code by running that same analyze phase, so there is no second front end to hide behind
  and no build flag that makes analysis inert. The M3 trust gate now ships: `analysable`
  gates `ensureAnalyzed` and `refresh` by path containment on decoded paths, and a client
  that declares no root runs unguarded. It is a containment control, not a sandbox —
  analysis still executes code inside the roots.
- A `.s7i` buffer is analysed through a synthetic driver that reads the file from disk,
  so unsaved library edits report stale diagnostics. Known, recorded as R-F10; it was
  scheduled for M3 and split into its own plan, so it is still open — what closes is the
  silence, not the staleness: `refresh` appends one `Information` diagnostic per publish,
  `src/lsp_server.sd7`'s `LIB_STALE_MESSAGE`, for a `.s7i` buffer and for no other document,
  and `didClose` publishes the empty list. The route stays because the interpreter will not
  take a library's own text once that library sits inside `seed7_05.s7i`'s include closure:
  184 of the 214 top-level libraries analyse clean from text and 29 redeclare
  (`basearray.s7i` 2 names, `null_file.s7i` 44); the 30th NOISY row, `multiscr.s7i`, is NOISY
  on either route, so it is not a route split. Probe, figures and the scratch-path control:
  *R-F10 — the two routes, measured* in `docs/seed7-cli.md`.
- The `-32603` containment net in `main.sd7` is reached by one raise, and that raise answers no
  frame — so the bullet's old word `unreachable` was measured wrong while its safety holds. What it
  claimed held of `parseStri`, which does not raise on any input the server can receive (a
  truncated buffer is the normal state while typing, and the scanner terminates at EOF without
  raising), and of the reflection walk, wrapped in a guard that catches `RANGE_ERROR`,
  `INDEX_ERROR`, and `ILLEGAL_ACTION`; the `parseStri` call stays deliberately outside that guard —
  wrapping it would turn a raise into an empty diagnostic list, which publishes a falsely clean
  document. What reaches the block is `MEMORY_ERROR` from `readJson` on a request body nested deeply
  enough: `parseMessage`'s guard wraps only its own `readJson` call and names three other classes,
  so the raise arrives at `main.sd7`. The observable is `handler failed (memory)` on stderr and
  **no frame**: the raise happens before the id is read, `handlerFailed` echoes `msg.idJson`, and
  the loop-carried reset leaves it `null`, which `sendError`'s guard answers with silence. Keep the
  net, keep the reset — deleting the reset turns that same body into a second `-32603` frame under
  the *previous* message's id. And keep the bullet understood as conditional in its other
  direction too: `doc_index.sd7`'s `openUtf8` reader raises `RANGE_ERROR` on a file whose bytes
  are not valid UTF-8 (the measured raiser is `prg/err.sd7:89`), and the `catch` beside that open
  is what stops
  it reaching the request path, so it is not dead code.
  The byte sequence, the refuted `C0 80` claim and the command:
